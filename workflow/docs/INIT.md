# INIT — 프로젝트 초기화 절차

> **이 문서는 에이전트가 읽고 그대로 실행한다.**
> 사람은 폴더에 문서를 두고 이 파일의 경로를 줄 뿐이다.

관련 문서 — 같은 레포 안에서 상대 경로로 참조한다.

| 필요할 때 | 문서 |
| --- | --- |
| 받은 문서를 검사할 때 | `DOC-SCHEMA.md` 10절 |
| 하네스를 설치할 때 | `HARNESS.md` |
| 파일 원본이 필요할 때 | `templates/` |

**필요한 것만 열어라.** 처음부터 전부 읽지 않는다.

> **[llm-labs]** 초기화 대상은 **연습 폴더 하나**(`NN-category/NN-name/`)다. 이 문서의
> "프로젝트"·"루트"는 따로 적지 않는 한 그 연습 폴더를 뜻한다. `docs/INTENT.md`·`CLAUDE.md`·
> `.claude/`·`.gitignore`·git 저장소는 **저장소**에 하나씩 있고 모든 연습이 공유한다
> (`../WORKFLOW.md` 0절).

## 0. 하지 않을 것

먼저 읽는다. 아래는 어떤 상황에서도 하지 않는다.

| 금지 | 이유 |
| --- | --- |
| 받은 문서를 고친다 | 요구가 사람 것이 아니게 된다 |
| 빠진 블럭을 대신 채운다 | 같음. **보고하고 멈춘다** |
| `INTENT.md`를 스스로 바꾼다 | SSOT다. 사람의 요청으로만 고친다 |
| (모드 C) 참조하는 기존 프로젝트를 수정·삭제한다 | 남의 프로젝트가 바뀐다. **읽기만** |
| backlog CLI를 설치·재구현한다 | 프로젝트마다 다른 버전이 생긴다 |
| 이 가이드를 프로젝트로 복사한다 | 원본이 갱신돼도 옛 사본을 따른다. **[llm-labs]** `workflow/`를 연습 폴더로 복사하지 않는다(`ADVERSARIAL-REVIEW.md`만 예외, 6절) |
| **[llm-labs]** 연습 폴더에 `INTENT.md`를 만든다 | SSOT가 여러 벌이 된다. 저장소 `docs/INTENT.md` 하나를 쓴다 |
| **[llm-labs]** 다른 연습 폴더를 고친다 | 연습끼리 독립이다. 공통 코드가 필요하면 복사해 온다 |
| `docs/history/` 아래 기존 파일을 수정·삭제한다 | 기록이 사후에 바뀐다 |
| `src/`·`tests/` 같은 빈 폴더를 미리 만든다 | 안 쓰는 폴더가 남고 구조가 굳는다 |
| 코드를 쓴다 | 초기화는 구조를 세우는 일이다. 구현은 그다음 |

## 1. 어느 모드인지 판별

| 상태 | 모드 |
| --- | --- |
| `docs/current/`가 없고, 참조하는 기존 프로젝트가 없다 | **A — 신규** (`v0.1`) |
| `docs/current/`가 없고, 기존 프로젝트를 참조한다 | **C — 참조 후 신규** (`v0.1`) |
| `docs/current/`가 있다 | **B — 새 버전** (`v0.2`+) |

`docs/current/`의 유무로 `v0.1`인지 `v0.2`+인지 갈린다. **A와 C는 구조상 같고**
(둘 다 `v0.1` 신규), C는 기존 프로젝트를 **읽기 전용 참고 자료**로 본다는 점만 다르다
(`WORKFLOW.md` 4절). 사람이 "기존 프로젝트를 참고한다"고 알려주면 C다.

**[llm-labs]** `docs/current/`는 **그 연습 폴더의 것**을 본다. 07 카테고리처럼 `D:\projects`의
기존 도구를 읽기 전용으로 참조하는 연습은 C다.

판별한 결과를 먼저 말하고 시작한다.

### 8번 — 이전 BRIEF 대조

`docs/history/vX.Y/BRIEF.md`와 `docs/current/BRIEF.md`를 읽고, **무엇이 달라졌는지
요약해서 사람에게 확인받는다.**

읽는 순서가 있다.

1. 이번 `BRIEF`의 **"이전 버전에서 아쉬웠던 것"** — 사람이 직접 쓴 것이다. 이게 기준
2. 이전 `PROGRESS.md`의 **"계획 외 개선"** — 지난 버전에서 계획 밖으로 붙은 것
3. 두 `BRIEF`의 "이번 버전에서 풀고 싶은 문제" 비교

새 문서가 `INTENT.md`에 어긋나지 않는지도 함께 본다. 어긋나면 보고한다
(`DOC-SCHEMA.md` 1절 SSOT 정합성).

**요약 형식**

```
이전 버전 (v0.1) — 무엇을 하려 했나
이번 버전 (v0.2) — 무엇을 하려 하나
달라진 점 — 세 줄 이내
지난 버전 계획 외 개선 중 이번에 반영된 것 / 안 된 것
INTENT 정합성 — 어긋나는 곳 있나 (있으면 보고)
```

**사람이 승인할 때까지 다음으로 가지 않는다.** 요구를 잘못 읽은 채 Phase를 다 돌면
그때는 되돌리기 어렵다.

## 6. 하네스 설치

절차와 내용은 `HARNESS.md`를 따른다. 여기서는 결과만 정한다.

**[llm-labs]** `CLAUDE.md`·`.claude/`는 **저장소 루트**에 하나다. 첫 연습의 INIT에서만
설치하고, 이후 연습에서는 아래 상태인지 점검만 한다. `docs/ADVERSARIAL-REVIEW.md`와
`docs/reviews/`는 **연습 폴더 안**에 연습마다 만든다.

| 대상 | 상태 |
| --- | --- |
| `CLAUDE.md` | 저장소 루트에 있고, 첫 줄에 가이드 버전이 적혀 있다 |
| `.claude/rules/` | 경로별 금지 규칙 |
| `.claude/hooks/` | `PreToolUse` — history·backlog 직접 편집 차단 |
| `.claude/agents/` | 리뷰어 |
| `.claude/settings.json` | hook 등록 |
| `docs/ADVERSARIAL-REVIEW.md` | 가이드의 사본. 절차를 프로젝트 안에서 읽을 수 있게 둔다 |
| `docs/reviews/` | 빈 폴더. Phase별 검토 기록 `A{n}.md`가 여기 쌓인다 |

`docs/ADVERSARIAL-REVIEW.md`는 **가이드에서 복사한다.** 이것만은 프로젝트 안으로
들어오는데, 검토가 구현 세션 밖의 별도 CLI에서 돌아가 가이드 경로를 못 보기 때문이다.
복사본을 고치지 않는다 — 절차가 바뀌면 가이드를 고치고 다시 복사한다.
**[llm-labs]** 복사 원본은 `workflow/docs/ADVERSARIAL-REVIEW.md`다.

`CLAUDE.md` 첫 줄:

```
project-workflow v0.2 기준으로 초기화됨 (2026-09-07)
```

**[llm-labs]** 첫 줄은 이 사본 기준으로 적는다.

```
workflow/ (project-workflow 3311e8f의 llm-labs 사본) 기준으로 초기화됨 (YYYY-MM-DD)
```

가이드가 갱신되면 예전에 초기화한 프로젝트와 구조가 달라진다. 기록이 없으면
나중에 왜 다른지 알 수 없다.

**B의 경우** — 하네스는 프로젝트 층이므로 이미 있다. 새로 깔지 않는다.
`DECISIONS.md`에서 `CLAUDE.md`·`rules`로 승격된 항목이 반영됐는지만 확인한다.

## 7. 차단 증명 — A·C에서만

**등록된 것과 동작하는 것은 다르다.** 경로 오타나 종료 코드 문제로 조용히
무력화되는 일이 흔하다.

가짜 입력으로 실제 막히는지 확인한다.

| 시도 | 기대 |
| --- | --- |
| `docs/history/` 아래 파일 수정 | 차단됨 |
| `backlog.json` 직접 편집 | 차단됨 |
| **[llm-labs]** 이 연습 폴더의 코드 파일만 바꾸고 그 연습의 `PROGRESS.md`는 그대로 둔 채 Stop hook 실행 | 차단됨(종료 코드 2) |

**[llm-labs]** 시도 경로는 이 연습 폴더 아래로 잡는다(`HARNESS.md` 5절).

**막히지 않으면 초기화 실패다.** 보고하고 멈춘다. 등록만 하고 넘어가면 있으나
마나 한 장치가 된다.

## 9. 멈춤 규칙

아래 상황에서는 **판단하지 말고 멈춘다.** 사람에게 무엇이 문제인지 말하고 기다린다.

- backlog CLI가 없다 (`backlog`를 쓰는 프로젝트일 때)
- `INTENT.md`(**[llm-labs]** 저장소 `docs/`) 또는 필수 버전 문서 중 하나라도 없다
- 문서 검사에 실패한 항목이 있다
- 버전 표기가 서로 다르거나 직전 버전보다 낮다
- 직전 버전이 마감되지 않았다 (B)
