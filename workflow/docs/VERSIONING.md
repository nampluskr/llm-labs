# VERSIONING — 버전 전환과 기록

버전을 언제 닫고, 무엇을 어디에 남기는지 정의한다.

`INIT.md`가 새 버전을 시작할 때 **"직전 버전이 마감됐는가"** 를 확인한다.
그 판정 기준이 이 문서다.

---

## 1. 버전 번호

두 단계다. `v<major>.<minor>` — 세 번째 자리는 쓰지 않는다.

| | 뜻 | 누가 정하나 |
| --- | --- | --- |
| **minor** | 이번 작업 묶음이 끝났다 | **사람** |
| **major** | 프로그램이 한 단계 완성됐다 | **사람** |

- `v0.x` — 만들어 가는 중. **MVP가 `v0.1`**
- `v1.0` — 목적한 것이 동작하고 실제로 쓰기 시작

**major·minor 모두 사람이 정한다. 자동 규칙은 없다.** "이러이러하면 major"처럼
기계가 판정하는 기준을 두지 않는다. 에이전트는 버전 번호를 스스로 올리지 않는다 —
사람이 프로그램의 완성도를 보고 번호를 말하면 그 번호로 진행한다.

`INTENT.md`가 바뀌는 것과 버전 번호는 **아무 관계가 없다.** INTENT를 고쳤다고 버전이
오르지 않고, 버전이 올라도 INTENT를 새로 쓰지 않는다 (`DOC-SCHEMA.md` 2절).

**번호는 재사용하지 않는다.** 중단한 버전도 번호를 소비한다. 8절.

---

## 2. 마감이 아닌 것

**전 Phase 완료는 마감이 아니다.**

backlog를 다 소진해도(backlog를 안 쓴 프로젝트면 `PLAN`의 전 Phase를 끝내도) 사람이
써보고 손볼 곳이 나온다. 그 검토 루프까지 끝나야 그 버전이다. 여기서 나온 개선은
**backlog에 넣지 않고** `PROGRESS.md`의 "계획 외 개선"에 적는다.

---

## 3. 마감 조건

넷 다 충족해야 마감할 수 있다.

| # | 조건 | 판정 |
| --- | --- | --- |
| 1 | `PLAN.md`의 전 Phase 완료 | `backlog` 상태(없으면 Phase 완료 조건) |
| 2 | 각 Phase 검증 게이트 통과 | 테스트·리뷰 기록 |
| 3 | 검토 루프 종료 | **사람이 "더 없다"고 판단** |
| 4 | `PROGRESS.md`에 빠진 항목이 없다 | task 수와 기록 수 대조 |

3번은 기계가 판정할 수 없다. 써본 사람만 안다.

## 4. 마감 절차

| # | 할 것 | 주체 | 종료 조건 |
| --- | --- | --- | --- |
| 1 | 마감 조건 4개 확인 | 에이전트 | 표로 보고 |
| 2 | 마감 선언 · 버전 번호 확정 | **사람** | 승인 |
| 3 | `PROGRESS.md` 마무리 — 이번 버전 요약 추가 | 에이전트 | 5절 |
| 4 | 승격 판정 — `DECISIONS.md` 항목 분류 | 에이전트 | 6절. **사람 승인** |
| 5 | `README.md` 갱신 | 에이전트 | 7절. **사람 승인** |
| 6 | `docs/history/vX.Y/` 생성 | 에이전트 | 폴더 존재 |
| 7 | `docs/current/`의 문서를 **`INTENT.md`만 빼고 복사** | 에이전트 | 8절 |
| 8 | 복사본과 원본 대조 | 에이전트 | 차이 없음 |
| 9 | 커밋 · `git tag vX.Y` · push. **[llm-labs]** 태그는 `<연습명>/vX.Y` (예: `01-01-local-chat/v0.1`) | 에이전트 | tag 존재 |
| 10 | **[llm-labs]** 저장소 `docs/ROADMAP.md` 진행 현황에 마감한 버전 기록 | 에이전트 | 갱신됨 |
| 11 | 보고 | 에이전트 | — |

**[llm-labs]** 이 절차는 **연습 폴더 하나**에 대해 돈다. `docs/current/`·`docs/history/`·
`README.md`·`PROGRESS.md`는 모두 그 연습 폴더의 것이다. 연습마다 버전 번호가 따로이므로
다른 연습의 버전과 무관하다. `<연습명>`은 카테고리 번호-연습 번호-연습 이름이다
(`02-bench/01-model-bench` → `02-01-model-bench`).

### 7번 — `INTENT.md`는 복사하지 않는다

`docs/current/`의 문서를 history로 복사하되 **`INTENT.md`는 제외한다.** 나머지
(`BRIEF`·`DECISIONS`·`SPEC`·`PLAN`·`backlog`·`PROGRESS`) 중 있는 것을 그대로 복사한다.

**왜 INTENT만 빼나** — INTENT는 SSOT다. "지금 유효한 하나"만 의미가 있고, 과거 버전의
의도 스냅샷을 남기는 문서가 아니다. history에 복사하면 버전마다 같은(또는 조금씩
다른) INTENT가 여러 벌 쌓이고, 어느 것이 진짜인지 흐려진다. INTENT는 항상
`docs/current/`에 단 하나만 있다 (`DOC-SCHEMA.md` 2절).

**[llm-labs]** 연습 폴더의 `docs/current/`에는 처음부터 INTENT가 없다. INTENT는 저장소
`docs/`에 하나다. 연습 폴더 안에서 INTENT가 보이면 복사하지 말고 보고한다.

**`docs/current/`는 비우지 않는다.** 그대로 둔다.

마감했다고 그 버전이 과거가 되는 것이 아니다. 새 버전을 시작하기 전까지
**현재 유효한 버전은 여전히 그것**이다. `docs/current/`를 비우면 그 구간에
프로젝트를 열었을 때 참조할 문서가 없다.

교체는 다음 버전 착수 시점에 `INIT.md`가 한다. 그때도 `INTENT.md`는 지우지 않는다.

**옮기지 않고 복사하는 이유** — 복사는 원본을 건드리지 않는다. 실패해도 기록이
사라지지 않는다.

## 5. `PROGRESS.md` 마무리

마감 시점에 요약 블럭을 하나 덧붙인다. 지금까지 쌓인 것은 건드리지 않는다.

| 항목 | 담는 것 |
| --- | --- |
| 계획 대비 | task 총 수 / 완료 수 |
| 계획 외 개선 | 건수와 한 줄 요약 |
| 남긴 것 | 이번에 안 한 것과 이유 |
| 다음 버전으로 | 검토에서 나왔지만 미룬 것 |

**마지막 두 항목이 다음 버전 `BRIEF`의 재료다.** 여기 적어두지 않으면 다음 버전을
시작할 때 기억에 의존하게 된다.

## 6. 승격 — 결정을 강제되는 자리로

`DECISIONS.md`의 각 항목을 성격에 따라 나눈다.

| 성격 | 어디로 | 예 |
| --- | --- | --- |
| 앞으로 지켜야 할 **제약** | `CLAUDE.md` · `.claude/rules/` | "torch 버전을 올리지 않는다" |
| 왜 그렇게 정했나 하는 **근거** | 여기 남아 history로 | 왜 그 버전으로 고정했나 |

**근거는 옮기지 않는다.** `history/v0.1/DECISIONS.md`에 영구히 있고, 나중에
"왜 이 규칙이 생겼나"를 물을 때 거기서 찾는다.

**왜 승격이 필요한가** — 버전 문서는 버전마다 새로 쓰인다. 계속 유효한 제약을
`DECISIONS.md`에만 두면 매 버전 옮겨 적어야 하고, 빠뜨리면 조용히 사라진다.
`CLAUDE.md`는 매 세션 자동 로드되고 `rules`는 해당 경로 작업에 적용된다.

**[llm-labs]** `CLAUDE.md`는 저장소 루트에 하나라 **모든 연습**에 걸린다. 한 연습에만
걸리는 제약은 `CLAUDE.md`가 아니라 그 연습 폴더 경로에 걸리는 `.claude/rules/` 규칙으로
승격한다. 모든 연습에 걸릴 제약만 `CLAUDE.md`로 올린다. 어느 쪽인지는 사람이 정한다.

**승격 항목은 사람이 승인한다.** 에이전트가 "이건 계속 지켜야 한다"를 혼자
정하면 `CLAUDE.md`가 불어난다. `CLAUDE.md`는 짧아야 읽힌다.

승격했으면 `CLAUDE.md`에 출처를 남긴다.

```
- torch 버전을 올리지 않는다 (v0.1 D-3)
```

**[llm-labs]** 출처에 연습명을 붙인다 — `(01-01-local-chat v0.1 D-3)`.

## 7. `README.md` 갱신

`README.md`는 프로젝트를 밖에서 소개하는 문서다 — 개요·설치·사용법
(`DOC-SCHEMA.md` 9절). 마감 때 이번 버전의 결과를 반영한다.

| 블럭 | 마감 시 |
| --- | --- |
| 개요 | `INTENT.md`가 바뀌었으면 그에 맞춰 손본다 |
| 설치·사용법·요구 환경 | **실제로 동작하는 것 기준으로 갱신** |

설치·사용법은 계획이 아니라 결과의 기록이다. 이번 버전에서 실제로 되는 것만 적는다.
`SPEC`에 있었지만 안 된 것은 적지 않는다.

개요는 프로젝트 정체성의 원천이 아니다 — 그건 `INTENT.md`다. README 개요는 INTENT를
밖으로 풀어 쓴 소개이므로, INTENT와 어긋나지 않게만 맞춘다. **README를 고쳤다고 버전
번호가 오르지 않는다** (버전은 사람이 정한다, 1절).

`README.md`는 루트에 남는다. history로 가지 않는다. 과거 상태는 `git tag`로 본다.
**[llm-labs]** 여기서 `README.md`는 연습 폴더의 것이고, 개요는 저장소 `docs/INTENT.md`와 그
연습의 BRIEF에 어긋나지 않게 맞춘다.

## 8. 버전을 중단할 때

전 Phase를 못 끝내고 접는 경우다.

| # | 할 것 |
| --- | --- |
| 1 | `PROGRESS.md` 마지막에 **중단 블럭** 추가 — 어디까지 했나, 왜 접나 |
| 2 | `docs/history/vX.Y/`에 복사 — **`INTENT.md`만 빼고.** 마감과 같다 |
| 3 | **`git tag`는 붙이지 않는다** |
| 4 | 다음 버전은 **그다음 번호**로 시작한다 |

**번호를 소비한다.** `v0.2`를 접었으면 다음은 `v0.3`이다.

재사용하면 `history/v0.2/`가 둘이 되고, "무엇을 시도했다 접었나"가 기록에서
사라진다. 접은 것도 그 프로젝트에서 일어난 일이다.

tag를 안 붙이는 이유 — tag는 "여기까지 동작한다"는 표시다. 중단한 버전에는
그 의미가 없다. `history/`에 있고 `PROGRESS.md`에 사유가 있으면 충분하다.

## 9. 마감 검사 목록

`INIT.md`가 새 버전을 시작할 때 이 목록으로 직전 버전을 확인한다.
**하나라도 걸리면 새 버전을 시작하지 않는다.**

| 검사 |
| --- |
| `docs/history/vX.Y/`가 있다 |
| 그 폴더에 직전 버전 문서가 다 있다 (`INTENT.md`는 없어야 정상 — 복사 대상이 아니다) |
| **[llm-labs]** 저장소 `docs/INTENT.md`가 있고, 연습 폴더 안에는 없다 |
| `PROGRESS.md`에 요약 블럭 또는 중단 블럭이 있다 |
| 마감이면 `git tag <연습명>/vX.Y`가 있다 (**[llm-labs]**) |
| `README.md`가 갱신돼 있다 |

## 10. history 폴더 규칙

**쓰기 후 불변이다.**

| 허용 | 금지 |
| --- | --- |
| 마감 시 폴더 생성과 복사 | 기존 파일 수정 |
| 읽기 — `INIT.md`의 `BRIEF` 대조 | 기존 파일 삭제 |
| | 폴더 이름 변경 |

hook이 판정할 규칙은 한 줄이다 — *`docs/history/` 아래 이미 있는 파일은 수정도
삭제도 막는다.* 설치는 `HARNESS.md`.

**마감한 버전은 고치지 않는다.** 세 번째 자리가 없으므로 수정은 다음 minor로
넘긴다.
