# DECISIONS — 00-02 env-check

## D-1. 점검 도구는 화면 없는 Python CLI다

- **선택:** `env-check`는 argparse로 만든 Python CLI다. 화면은 없다. pywebview는 창이 뜨는지 확인하는 용도로만
  쓴다.
- **근거:** 화면이 필요 없는 연습은 Python CLI로 만든다(저장소 DECISIONS R-9). 이 연습의 결과물은 점검 출력과 종료
  코드다.
- **배제한 대안:**
  - pywebview로 점검 결과 화면 만들기 — 점검에 화면이 필요 없고 BRIEF 4절이 GUI 앱을 범위 밖으로 둔다.
  - Electron — 저장소가 쓰지 않기로 했다(R-9).

## D-2. 환경은 이 연습 폴더의 uv 프로젝트이고 Python은 3.13이다

- **선택:** 이 연습 폴더에 `pyproject.toml`을 두고 uv로 환경을 만든다. Python은 3.13으로 고정한다(`uv init
  --python 3.13`, `.python-version`).
- **근거:** 연습마다 `pyproject.toml`을 둔다(R-10). 연습 플랜의 기술 스택이 Python 3.13이다. 이 PC에는 uv가 받은
  3.13.14와 3.14.6이 모두 있는데, 지정하지 않으면 `uv python find`가 3.14를 고른다.
- **배제한 대안:**
  - 저장소 루트에 `pyproject.toml` 하나 — 한 연습의 의존성 변경이 다른 연습에 영향을 준다(R-10).
  - PATH의 `python` — Microsoft Store 별칭이라 쓰지 않는다(`AGENTS.md`).
  - 버전 미지정(3.14) — 플랜의 기준과 달라지고, 이후 연습이 이 연습의 설정을 복사해 갈 때 버전이 어긋난다.

## D-3. 점검은 읽기 전용 API만 쓰고 모델을 적재하지 않는다

- **선택:** Ollama의 `/api/version`, `/api/tags`, `/api/ps`만 호출한다. 모델을 적재하는 요청(`/api/generate`·
  `/api/chat` 등)은 보내지 않는다.
- **근거:** 이미 적재된 모델이 있을 때 PROCESSOR가 평상시 점유(약 1.8GB)와 섞이지 않게 현재 상태만 읽는다. 읽기
  전용이라 VRAM을 추가로 쓰지 않는다(플랜 4절).
- **배제한 대안:** 점검 중 작은 모델을 적재해 GPU 동작까지 확인하기 — 적재 자체가 상태를 바꿔 점검 대상(현재
  상태)이 달라지고, GPU 적재 확인은 00-01에서 끝났다.

## D-4. 점검 범위는 Ollama 상태까지이고, GPU·디스크 점검은 넣지 않는다

- **선택:** 점검 항목은 Ollama 서버 연결·버전·받은 모델 목록·적재된 모델과 PROCESSOR다. `nvidia-smi` VRAM·드라이버
  버전·디스크 여유는 점검하지 않는다.
- **근거:** 플랜의 Phase 2·3 완료 조건이 이 항목들로 정해져 있다. 확장 항목은 플랜에서 "미정"이었고 사용자가 이번
  버전에서 하지 않기로 했다(BRIEF 4절). GPU 적재 상태는 `/api/ps`의 PROCESSOR로 본다.
- **배제한 대안:** `nvidia-smi`·디스크 여유까지 한 번에 점검하기 — 항목이 늘면 Phase 2·3의 완료 조건과 검증이
  함께 커진다. 필요해지면 새 버전에서 정한다.

## D-5. 결과는 화면과 `--json`으로만 내고, 실패는 종료 코드 1이다

- **선택:** 점검 항목마다 통과/실패 한 줄과 전체 결과를 출력하고, `--json`은 같은 내용을 JSON으로 낸다. 서버를 껐을
  때는 오류 문구를 출력하고 종료 코드 1로 끝난다. 결과를 파일로 저장하지 않는다.
- **근거:** 플랜 Phase 2·3의 완료 조건이다. 반복 실행하는 점검이라 종료 코드로 성패를 알 수 있어야 한다. 파일 저장은
  이번 버전에서 하지 않기로 했다(BRIEF 4절).
- **배제한 대안:**
  - 결과를 파일로 남기기 — 사용자가 이번 버전 범위 밖으로 정했다.
  - 서버가 꺼져도 종료 코드 0으로 끝내기 — 반복 실행·스크립트에서 실패를 구별할 수 없다.

## D-6. CUDA 환경을 따로 두지 않고 winpython 환경을 쓰지 않는다

- **선택:** 이 연습은 CUDA Toolkit·torch 등 GPU 파이썬 패키지를 설치하지 않는다. `C:\winpython\WPy64-31180_gpu`
  환경도 쓰지 않고, D-2의 uv 환경(Python 3.13)만 쓴다. GPU는 Ollama가 쓰고, 이 연습의 코드는 Ollama API를
  읽기만 한다.
- **근거:** Ollama는 자체 CUDA 런타임을 포함해 CUDA Toolkit이 필요 없고 NVIDIA 드라이버만 있으면 된다(00-01에서
  572.70 확인, `docs/refs/01-hardware.md` 2절). winpython `_gpu` 환경 정보는 같은 문서 4절이다. winpython `_gpu`는 Python 3.11.8이라 D-2의 3.13과 다르고
  pywebview·plotly가 없어 Phase 1(pywebview 창 확인)을 할 수 없다. 다른 도구가 함께 쓰는 공용 환경이라 연습
  의존성이 섞이면 영향을 준다.
- **배제한 대안:**
  - winpython `_gpu` 환경 사용 — 위 이유로 D-2와 R-10(연습별 환경)에 어긋난다.
  - 연습 환경에 torch(CUDA 빌드)·CUDA Toolkit 설치 — 점검 CLI가 GPU를 직접 쓰지 않으므로 필요 없다. 파이썬 안에서
    모델을 직접 돌리는 연습이 생기면 그 연습의 DECISIONS에서 INTENT와 대조해 정한다.
