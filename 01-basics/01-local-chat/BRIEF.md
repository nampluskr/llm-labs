# BRIEF — 01-01 local-chat

## 1. 배경

00 환경 준비 다음의 첫 연습이다(`docs/ROADMAP.md`). Electron·pywebview 앱을 만들며 연습해 왔고, 다음
주제로 이 PC에서 Ollama로 돌리는 로컬 LLM을 직접 다뤄 보려 한다(`docs/INTENT.md`). 이후 연습들도 모두
"Ollama 호출 + 스트리밍 + 화면 갱신"이 필요하므로, 그 골격을 여기서 처음 만든다.

이 연습은 Ollama가 설치되고 모델이 받아져 있는 상태에서 시작한다. 설치와 모델 받기는 00-01
ollama-setup, 파이썬 환경 확인은 00-02 env-check에서 한다. 연습 플랜은
`docs/labs/01-basics/01-local-chat.md`에 있다.

## 2. 이번 버전에서 풀고 싶은 문제

로컬 Ollama 모델과 대화하는 pywebview 채팅 앱을 만든다. 답변이 토큰 단위로 흘러나오고, 대화
중에 모델을 바꿀 수 있으며, 대화를 파일로 저장·불러온다. 이 과정에서 이후 연습이 복사해 쓸
공통 코드를 만든다.

Ollama를 부르는 방식 세 가지 — 공식 `ollama` 클라이언트, `langchain-ollama`, HTTP API 직접 호출 —
를 각각 쓰는 채팅 앱 3개를 만들어, 방식마다 무엇이 다른지 직접 비교한다. 앞으로 langchain·
langgraph를 쓸 예정이라 `langchain-ollama`도 여기서 다뤄 본다.

앱을 만들기 전에, 세 호출 방식의 기본 코드를 이해하고 공부할 수 있도록 Jupyter 노트북을 따로
만든다.

## 3. 이전 버전에서 아쉬웠던 것

해당 없음 (v0.1).

## 4. 하지 않을 것

- 공통 코드를 다른 연습을 예상해 미리 넓히는 일. 01-01·02-01에 실제로 필요한 것만 만든다.
- 공통 코드를 저장소 루트의 `shared\`에 두는 일. 쓰는 연습이 자기 폴더로 복사해 쓴다.
- 문서를 첨부해 그 내용을 근거로 답하는 기능(RAG). 03-rag에서 한다.
- 도구 호출·에이전트. 05-agent에서 한다.
- 이미지 입력. 06-vision에서 한다.
- 모델 받기(pull)·삭제 같은 모델 관리. 01-03 model-manager에서 한다. 여기서는 이미 받은 모델 목록만 쓴다.

## 5. 완료 조건

- 세 호출 방식의 기본 코드를 담은 노트북이 오류 없이 실행된다
- 연습 플랜(`docs/labs/01-basics/01-local-chat.md`)의 앱 Phase 완료 조건을 세 호출 방식의 앱
  모두에서 만족한다
- 구현이 반대 벤더 적대적 검증을 통과하고, 그 기록이 남아 있다
- 이후 연습이 복사해 갈 수 있도록, 공통 코드가 화면 코드와 분리돼 있다
