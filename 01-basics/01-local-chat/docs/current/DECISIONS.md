# DECISIONS — 01-01 local-chat

## D-1. 공통 코드를 두는 곳

- **선택:** Ollama 호출·스트리밍 같은 공통 코드는 이 연습 폴더 안에 둔다. 이후 연습은 필요한
  부분을 자기 폴더로 복사해 쓴다.
- **근거:** 연습끼리 독립시킨다. 한 연습에서 공통 코드를 고쳐도 다른 연습이 깨지지 않는다
  (2026-10-04 저장소 결정).
- **배제한 대안:**
  - 저장소 루트 `shared\`에 두고 여러 연습이 같이 쓰기 — 버전이 없는 공유 코드를 고치면 다른 연습이 깨질 수 있다.
  - `shared\`를 버전 있는 별도 프로젝트로 두기 — 가장 엄격하지만 연습 저장소에는 무겁다.

## D-2. 런타임

- **선택:** Python + pywebview
- **근거:** 앞으로 langchain·langgraph 같은 파이썬 라이브러리를 쓸 것이므로, 모든 UI는 pywebview로
  만든다. 이 연습에 파이썬 연산(numpy·차트)이 없어도 같은 기준을 따른다.
- **배제한 대안:** Electron — 파이썬 라이브러리를 쓸 수 없고, 이후 연습이 복사해 쓸 공통 코드가
  파이썬이 아니게 된다.

## D-3. Ollama 호출 방식

- **선택:** 세 가지 방식을 각각 만든다.
  1. 공식 파이썬 클라이언트 `ollama`
  2. `langchain-ollama`
  3. Ollama HTTP API 직접 호출
- **근거:** 사용자가 세 방식을 각각 만들어 보고 싶어 한다. 앞으로 langchain·langgraph를 쓸
  예정이라 `langchain-ollama`도 첫 연습에서 다뤄 본다.
- **형태:** 방식마다 따로 실행되는 채팅 앱 3개를 01-01 한 연습 안에서, v0.1에 모두 만든다. 화면
  (pywebview)은 하나로 두고 호출 층만 3개로 나누며, 실행 진입점이 3개다.
- **배제한 대안:**
  - 한 가지 방식만 쓰기 — 세 방식의 차이를 직접 볼 수 없다.
  - 앱 하나에서 호출 방식을 화면으로 전환하기 — 사용자가 앱 3개를 택했다.
  - 콘솔에서만 세 방식, 화면은 하나 — 사용자가 앱 3개를 택했다.
  - 별도 연습으로 분리(01-02·01-03로 번호 밀기, 01-06·01-07 추가, 새 카테고리) — 기존 번호와
    참조를 고치거나 01~07 카테고리의 5개씩 구성이 깨지고, 같은 화면 코드가 여러 벌 생기며, 비교가 흩어진다.
  - 버전으로 나누기(v0.1 한 방식, v0.2 나머지) — 사용자가 v0.1에 세 방식을 모두 넣기로 했다.

## D-4. 기본 모델

- **선택:** `qwen3:8b`를 기본으로 하고, `qwen3:4b`·`exaone3.5:7.8b`로 바꿀 수 있게 한다.
- **근거:** `docs/refs/01-hardware.md` 5.2절에서 `qwen3:8b`는 "여유" 판정이고 범용 기본 모델이다.
- **배제한 대안:** `exaone3.5:7.8b`를 기본으로 하기 — 한국어에 강하지만 범용 기본은 qwen3로 한다
  (바꿔 쓸 수는 있다).

## D-5. 컨텍스트 길이(`num_ctx`)

- **선택:** 기본 4096, 설정에서 8192까지.
- **근거:** `docs/refs/01-hardware.md` 5.2절 추정으로 8B급 모델은 4K~8K에서 VRAM에 여유가 있고, 32K에서는 남는 VRAM을 넘긴다.
- **배제한 대안:** 모델의 최대 컨텍스트를 그대로 쓰기 — KV cache 때문에 VRAM을 넘긴다.

## D-6. 모델을 바꿀 때 이전 모델 처리

- **선택:** 모델을 바꾸면 이전 모델에 `keep_alive: 0` 요청을 보내 바로 내린다.
- **근거:** Ollama는 이전 모델을 `keep_alive` 동안 메모리에 남긴다. 두 모델이 동시에 올라가면 VRAM을 넘길 수 있다(`docs/refs/01-hardware.md` 5.2절, 연습 플랜 4절).
- **배제한 대안:** Ollama 기본 동작(일정 시간 유지)에 맡기기 — 전환 직후 두 모델이 겹쳐 넘칠 수 있다.

## D-7. 대화 저장 형식

- **선택:** JSON
- **근거:** `/api/chat`의 `messages` 배열(role·content)을 그대로 저장하고 그대로 복원할 수 있다.
- **배제한 대안:**
  - Markdown — 사람이 읽기는 쉽지만 메시지 배열로 복원하기 어렵다.
  - SQLite — 연습에는 무겁다.

## D-8. Ollama 설치는 이 연습 밖(00-01)

- **선택:** Ollama 설치와 모델 받기는 00-01 ollama-setup, 파이썬 환경 확인은 00-02 env-check에서 한다.
  이 연습은 설치·모델 받기가 끝난 상태에서 시작한다. 설치는 사용자가 `docs/refs/02-ollama-install-guide.md`를
  보고 직접 한다.
- **근거:** 설치와 환경 준비는 01-01뿐 아니라 모든 연습의 전제다. 00 카테고리로 분리해 한 번만
  하고, 설치 확인(`ollama list`, `ollama ps`의 PROCESSOR)은 00-01의 완료 조건으로 둔다(저장소 DECISIONS R-13).
- **배제한 대안:**
  - 01-01의 첫 Phase로 두기 — 이 연습의 완료 조건에 모든 연습의 전제가 섞인다. (이 초안의 이전 결정이었다)
  - 에이전트가 설치하기 — 저장소 규칙상 하지 않는다.

## D-9. 세 호출 방식 노트북

- **선택:** 이 연습 폴더의 `notebooks/`에 방식마다 노트북을 하나씩, 3개 둔다 —
  `01-ollama.ipynb`, `02-langchain-ollama.ipynb`, `03-http-api.ipynb`. 앱보다 먼저 만든다.
- **근거:** 세 호출 방식의 기본 코드를 이해·공부하기 위해서다. 방식별로 따로 공부하기 좋다.
- **배제한 대안:**
  - 노트북 하나에 세 방식을 주제별로 나란히 — 비교는 쉽지만 파일이 길어진다.
  - 방식별 3개 + 비교 노트북 1개 — 사용자가 방식별 3개를 택했다.

## D-10. qwen3 사고 과정(`<think>`)

- **선택:** 사고 과정을 화면에 표시한다. 모델이 지원할 때만(`/api/show`의 `capabilities`에 `thinking`이 있을 때) `think=True`로 부르고, 지원하지 않는 모델에는 `think=False`로 부른다. 사고 과정은 답 위의 접이식 블록에 보인다 — 생각하는 동안은 펼쳐 두고, 답이 시작되면 접으며, 사용자가 다시 펼 수 있다. 사고 과정은 화면에만 보이고 다음 질문의 문맥에는 넣지 않는다.
- **근거:** 사용자가 사고 과정을 표시하기로 정했다(2026-10-04). 처음에는 끄고 표시하지 않기로 했으나(`think=False` 고정), 실제 Ollama로 확인하니 `qwen3:4b`는 `think=False`를 무시해 추론 과정이 영어 평문으로 답에 섞여 나왔다(인사 한마디에 1000토큰 이상, `thinking` 필드는 비어 있음). `think=True`로 부르면 `qwen3:8b`·`qwen3:4b` 모두 추론이 `thinking` 필드로 분리돼 답과 섞이지 않는다. 지원하지 않는 모델(`exaone3.5:7.8b`)에 `think=True`를 보내면 Ollama가 400을 내므로 `capabilities`로 먼저 확인한다.
- **배제한 대안:**
  - 사고 과정을 끄고 표시하지 않기(이전 선택) — `qwen3:4b`에서 끄기가 통하지 않아 답이 오염된다.
  - 항상 펼쳐 두기 — 답보다 사고 과정이 훨씬 길어(수백~천 토큰) 답이 밀려난다.
  - 사고 과정을 다음 질문의 문맥에 포함 — 컨텍스트(`num_ctx` 4096, D-5)를 불필요하게 쓴다.
  - 지원 여부를 `think=True` 시도 후 400이 나면 재시도 — 불필요한 실패 요청이 생기고 오류 문구에 의존한다.
