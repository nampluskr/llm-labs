# PLAN — 01-01 local-chat

SPEC은 두지 않는다. Phase마다 BRIEF 5절 완료 조건을 가리킨다.

**전제:** Ollama 설치와 모델 받기는 00-01 ollama-setup, 파이썬 환경 확인은 00-02 env-check에서
끝나 있다(저장소 DECISIONS R-13). 이 연습은 `qwen3:8b`·`qwen3:4b`·`exaone3.5:7.8b`가 받아져 있고
`ollama list`에 보이는 상태에서 시작한다.

## Phase 1 — 세 호출 방식 노트북

- **목적:** 세 호출 방식의 기본 코드를 이해·공부할 수 있는 노트북을 만든다(D-9).
- **BRIEF 완료 조건:** "세 호출 방식의 기본 코드를 담은 노트북이 오류 없이 실행된다"
- **완료 조건:** `notebooks/`의 `01-ollama.ipynb`·`02-langchain-ollama.ipynb`·`03-http-api.ipynb`가
  처음부터 끝까지 오류 없이 실행되고, 각각 스트리밍 응답과 tok/s를 출력한다.

## Phase 2 — 공통 호출 층

- **목적:** 노트북의 코드를 화면과 분리된 호출 층 3개로 옮긴다(D-1, D-3).
- **BRIEF 완료 조건:** "공통 코드가 화면 코드와 분리돼 있다"
- **완료 조건:** 호출 층 3개가 같은 인터페이스를 갖고, 콘솔에서 세 방식 모두 토큰을 순차 출력한 뒤
  tok/s를 한 줄 출력한다.

## Phase 3 — 채팅 화면(앱 3개)

- **목적:** pywebview 화면 하나를 세 호출 층에 붙여 앱 3개로 실행한다(D-2, D-3).
- **BRIEF 완료 조건:** "앱 Phase 완료 조건을 세 호출 방식의 앱 모두에서 만족한다"
- **완료 조건:** 세 앱 각각 pywebview 창에서 질문하면 답변이 스트리밍으로 표시되고, 직전 대화
  10턴이 문맥으로 전달된다.

## Phase 4 — 모델 전환·옵션

- **목적:** 대화 중 모델을 바꾸고 생성 옵션을 조절한다(D-4, D-5, D-6).
- **BRIEF 완료 조건:** 위와 같음
- **완료 조건:**
  - 세 앱 각각 `/api/tags`의 모델이 드롭다운에 모두 보이고, 바꾼 뒤 다음 질문부터 새 모델로 답한다.
  - 전환할 때 이전 모델에 `keep_alive: 0`이 보내진다.
  - `num_ctx`(4096~8192)·`temperature` 값이 요청에 실린다.

## Phase 5 — 대화 저장

- **목적:** 대화를 파일로 저장하고 불러온다(D-7).
- **BRIEF 완료 조건:** 위와 같음
- **완료 조건:** 세 앱 각각 대화를 JSON으로 저장하고, 다시 열면 같은 메시지 수로 복원된다.
