# PROGRESS — 01-02 prompt-playground

## 계획된 작업

### Phase 1 — 변형 실행 (완료)

- **무엇을 했나:** `src/prompt_playground/`에 변형 순차 실행(`runner.py`)과 스펙 JSON → 결과 JSON CLI(`__main__.py`)를 만들었다. `pyproject.toml`·`.python-version`(3.13)·`tests/test_runner.py`를 추가했다.
- **결과:** 변형 N개(1~6개, 범위 밖이면 `ValueError`)를 하나씩 순서대로 `qwen3:4b`(`think=True`, `num_ctx` 4096)에 보내고 결과 N개를 JSON 하나로 저장한다. 변형 하나가 실패해도 나머지는 계속하고 그 결과에 `error`를 담는다.
- **검증:** `uv run pytest` 9개 통과(순서·고정 모델·`think`·옵션 4종·6개 상한·실패 격리·JSON 저장·타임아웃/연결 오류 격리). 실제 Ollama `qwen3:4b`로 변형 3개를 실행해 결과 3개가 JSON에 저장됐고 오류는 없었다. 변형 하나에 20~46초(1300~2900토큰, 대부분 사고 과정)가 걸렸다. 세션 내 리뷰어(`reviewer`)가 검증했다. 반대 벤더 검증은 R-16에 따라 하지 않는다.
- **특이사항:** 리뷰어가 "미흡 2건"으로 판정했다. (1) `httpx.ReadTimeout` 같은 httpx 예외를 잡지 않아 변형 하나의 타임아웃이 나머지를 취소하고 앞선 결과도 저장되지 않는 문제 → `httpx.HTTPError`를 변형 하나의 실패로 담도록 고치고 테스트 3개를 추가했다(`httpx`를 직접 의존에 추가). (2) `PROGRESS.md` 기록 → 이 항목으로 해결했다. 리뷰어의 재검증은 하지 않았고, 수정 후 실제 모델 재실행도 하지 않았다(바뀐 곳은 예외 처리뿐이고 단위 테스트로 확인했다).
- **관찰:** 6개를 순차 실행하면 2~4분이 걸릴 수 있어 Phase 2의 화면에는 진행 표시가 필요해 보인다. 설계 결정이 아니라 관찰이며 Phase 2에서 다시 다룬다.

### Phase 2 — 나란히 보기 (완료)

- **무엇을 했나:** `webapp.py`(pywebview 창과 `Api`: 입력 검증, 한 번에 한 실행, 작업 스레드에서 순차 실행하며 결과마다 화면에 이벤트 전달, 끝나면 `out/playground-*.json` 저장)와 `ui/index.html`(프롬프트·변형 입력 행 1~6개, 결과를 열로 표시)을 만들었다. `[project.scripts]`에 `prompt-playground`를 등록했다.
- **결과:** 변형 N개를 실행하면 결과 N개가 열로 나란히 놓이고, 열마다 파라미터 값(`temperature`·`top_p`·`seed`·시스템 프롬프트)·생성 토큰 수·소요 시간이 보인다. 사고 과정은 접이식, 실패한 변형은 그 열에 오류를 표시한다. 열은 실행 전에 먼저 만들어 결과 이벤트가 열보다 먼저 도착하는 경쟁을 피하고, 지금 실행 중인 열에 "실행 중…"을 표시한다(Phase 1 관찰의 진행 표시).
- **검증:** `uv run pytest` 22개 통과(Api 입력 거절 8종·순서·중복 실행 거절·오류 뒤 busy 해제, 실제 창 GUI 테스트 1개: 변형 3개 입력→실행→열 3개와 파라미터·`N토큰 · X초`·본문·사고 과정 확인). 실제 `qwen3:4b`로 창을 구동해 변형 2개를 실행, 열 2개에 파라미터·1824토큰 29.057초·1302토큰 19.311초가 표시되고 JSON이 저장됐다. 세션 내 리뷰어(`reviewer`)가 "통과"로 판정했다(반대 벤더 검증은 R-16에 따라 하지 않는다). 열 N개 표시, 열마다 파라미터·토큰 수·소요 시간, 중복 실행·창 닫기·입력 검증 우회·XSS·범위 초과를 점검했고 막을 결함은 없었다.
- **리뷰어의 경미한 지적:** (2) 성공인데 `eval_count`가 없으면 "null토큰"이 표시됨 → `?`로 표시하도록 고쳤다. 나머지는 고치지 않았다. (1) 실행 거절 시 다른 실행이 돌고 있어도 입력이 풀림(정상 UI로는 도달 불가, 페이지를 다시 불러온 경우만). (3) GUI 테스트가 N=3 성공 경로만 보고 실패 열·N=1·6 경계·소요 시간 숫자 여부는 DOM 수준에서 검사하지 않음. (4) `seed`에 범위 제한이 없고 소수·`True`를 조용히 받음(BRIEF 요구 밖).
- **특이사항:** 창을 만들 때 `Windows fatal exception: code 0x8001010d` 스택 덤프가 로그에 섞이지만 테스트는 통과하고 종료 코드는 0이다(WinForms COM 소음으로 보이며 원인은 확인하지 않았다). `seed 1`·`temperature 1`·`top_p 0.9` 같은 조건의 실행이 Phase 1 실행과 같은 토큰 수(1302)와 같은 문장으로 나왔다. 재현성 판단은 Phase 3·4에서 하며 여기서는 판정하지 않는다.
