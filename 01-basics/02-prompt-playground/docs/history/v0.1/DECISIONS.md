# DECISIONS — 01-02 prompt-playground

## D-1. 학습용으로 하되 `seed` 재현성 검증 결과를 남긴다

- **선택:** 이 연습은 학습용이다. 다만 Phase 3에서 이 PC의 `seed` 재현성을 검증하고(같은 조건 5회 실행, 5회 출력이 모두 같은지 다른지 기록), 그 결과를 문서로 남겨 02-05 prompt-regression이 근거로 쓰게 한다.
- **근거:** `INTENT.md`가 이 저장소를 연습 공간으로 정하고 완성형 제품화를 다루지 않는다. 02-05는 `seed`와 `temperature: 0`으로 출력을 고정하는 연습이고, 그 플랜에 "GPU 연산 순서 차이로 seed를 고정해도 출력이 미세하게 달라질 수 있다"는 위험이 적혀 있다. 이를 01-02에서 먼저 확인해 두면 02-05에 직접 도움이 된다. 사용자가 이 안을 택했다(2026-10-05).
- **배제한 대안:**
  - 학습용으로만 한정하고 재현성 결과를 따로 남기지 않기 — 02-05가 같은 확인을 처음부터 다시 해야 한다.
  - 다른 연습에서 계속 쓸 도구로 키우기 — 연습 저장소의 범위(`INTENT.md` 4절) 밖이다.

## D-2. 비교 파라미터는 네 가지

- **선택:** `temperature`·`top_p`·`seed`·시스템 프롬프트 네 가지만 비교한다.
- **근거:** 입문자가 효과를 눈으로 확인하기에 네 가지로 충분하고, 늘리면 화면과 완료 조건이 커진다. 사용자가 플랜 그대로를 택했다(2026-10-05).
- **배제한 대안:**
  - `top_k`·`num_predict`(최대 출력 길이)를 추가 — 배울 것은 늘지만 이번 범위를 넘고 완료 조건이 커진다.

## D-3. 모델은 `qwen3:4b` 하나

- **선택:** 이 연습은 `qwen3:4b` 하나만 쓴다.
- **근거:** 02-05 prompt-regression이 `qwen3:4b`를 쓰므로 같은 모델이면 재현성 검증 결과가 그대로 이어진다(D-1). 파라미터 효과를 볼 때 모델 비교가 섞이지 않고, 모델이 하나라 VRAM에 겹쳐 올라갈 일이 없다. 사용자가 `qwen3:4b` 하나를 택했다(2026-10-05).
- **배제한 대안:**
  - `qwen3:8b` 하나 — 01-01에서 검증된 모델이고 품질이 낫지만, 02-05와 모델이 달라 재현성 결과가 그대로 통하지 않는다. 한 변형당 시간도 더 걸린다.
  - `qwen3:4b`로 실험하고 `qwen3:8b`로 전환 가능하게 하기 — 모델 전환 코드(이전 모델을 바로 내리는 처리)가 생기고, 파라미터 비교에 모델 비교가 섞인다.
  - `qwen3:8b` 하나로 하고 재현성 검증만 `qwen3:4b`로 한 번 더 — 모델 전환이 생겨 "하나만"이라는 의도와 어긋난다.
