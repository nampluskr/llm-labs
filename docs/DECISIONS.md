# DECISIONS — llm-labs (저장소 전체)

> 모든 연습에 걸리는 결정을 적는다. 한 연습에만 걸리는 결정은 그 연습의
> `docs/current/DECISIONS.md`에 둔다. 형식은 `workflow/docs/DOC-SCHEMA.md` 4절(결정·근거·배제한 대안)을 따른다.
> 연습별 내용 변경(예: 06-04 chart-reader → scan-ocr, 04-03에 md·pdf 번역 포함)은 여기가 아니라
> `docs/refs/03-project-list.md`와 각 연습 플랜에 있다.

## R-1. 저장소 위치

- **선택:** `D:\projects` 워크스페이스 밖, `D:\llm-labs`에 둔다.
- **근거:** 연습용 코드를 실사용 프로젝트와 분리한다(`INTENT.md` 2절).
- **배제한 대안:** `D:\projects` 안에 두기 — 연습 35개가 실사용 프로젝트 사이에 섞인다.

## R-2. 저장소 하나에 연습을 모은다

- **선택:** 연습 전부를 저장소 `llm-labs` 하나에 둔다.
- **근거:** 연습 코드가 흩어지면 관리가 어렵다(`INTENT.md` 2절).
- **배제한 대안:** 연습마다 개별 저장소(35개) — 흩어져 관리가 어렵다.

## R-3. 연습 폴더 배치

- **선택:** 저장소 루트에 `NN-category/NN-name/`으로 둔다. 연습 플랜은 `docs/labs/`에 두고, 구현
  폴더는 그 연습을 착수할 때만 만든다.
- **근거:** 연습 하나는 코드 조각이 아니라 문서·코드·환경을 갖춘 프로젝트 하나다(R-4).
- **배제한 대안:**
  - `src/` 아래에 연습 폴더를 두기 — 연습은 소스 코드가 아니라 프로젝트라 맞지 않는다.
  - 35개 폴더를 미리 만들기 — 안 쓰는 폴더가 남고 구조가 굳는다(`workflow/WORKFLOW.md` 9절).

## R-4. 버전은 연습마다

- **선택:** 저장소 루트는 버전 없는 워크스페이스 층이고, 연습 폴더 하나가 프로젝트 하나다. 버전·
  `docs/current/`·`docs/history/`·태그(`01-01-local-chat/v0.1`)는 연습마다 따로다.
- **근거:** 연습들은 서로 독립된 프로그램이다. 저장소 전체에 버전을 매기면 무관한 연습이 한
  버전에 묶이고, 한 연습을 고치려 해도 저장소 버전을 올려야 한다.
- **배제한 대안:**
  - 저장소 단위 버전(버전 = 연습 묶음) — 위 문제.
  - 버전 없이 연습마다 PLAN·PROGRESS만 — `INTENT.md` 3절(project-workflow 절차를 따른다)과 어긋난다.

## R-5. INTENT는 저장소 하나(`docs/INTENT.md`)를 공유한다

- **선택:** 연습 폴더에는 INTENT를 두지 않는다. 연습의 문서는 BRIEF·DECISIONS·PLAN·PROGRESS와
  README다.
- **근거:** 연습의 "무엇을 왜"는 `docs/labs/`의 연습 플랜 개요가 대신한다.
- **배제한 대안:**
  - 가이드 필수 세트 그대로(연습마다 INTENT) — 35벌의 INTENT가 생긴다.
  - 최소 세트(PLAN·PROGRESS·검증 기록만) — 가이드의 필수 문서 규칙과 어긋난다.

## R-6. 착수 순서는 ROADMAP에

- **선택:** 저장소 `docs/`에 버전 없는 `ROADMAP.md`를 두고 착수 순서·연습별 진행 현황·착수 때 넘길 것을 적는다.
  처음 쓴 저장소 BRIEF(연습 묶음 v0.1)는 이것으로 바꿨다.
- **근거:** 저장소 문서에는 버전이 없으므로 버전 문서인 BRIEF를 둘 수 없다.
- **배제한 대안:**
  - 저장소 BRIEF를 지우고 내용을 `docs/refs/03-project-list.md`·연습 BRIEF로 흩기 — 사용자가 로드맵 문서를 택했다.
  - 01-01 BRIEF 초안으로 재사용 — 같음.

## R-7. 공통 코드는 연습마다 복사한다

- **선택:** 저장소 루트에 공유 코드 폴더(`shared\`)를 두지 않는다. 쓰는 연습이 다른 연습의 코드를 자기
  폴더로 복사해 쓴다.
- **근거:** 연습끼리 독립시킨다. 한 연습에서 고쳐도 다른 연습이 깨지지 않는다.
- **배제한 대안:**
  - 루트 `shared\`(버전 없음) + 쓰는 연습 테스트를 함께 돌리기 — 고칠 때 다른 연습이 깨질 수 있다.
  - `shared\`를 버전 있는 별도 프로젝트로 — 가장 엄격하지만 무겁다.

## R-8. 가이드는 project-workflow를 고친 사본 `workflow/`

- **선택:** 원본 `D:\projects\project-workflow`(커밋 `3311e8f`)를 `workflow/`에 복사해 llm-labs 구조에
  맞게 고치고, 이 사본만 따른다. 원본은 고치지 않는다. 원본 갱신은 사용자가 판단해 반영한다
  (`workflow/UPSTREAM.md`). `ADVERSARIAL-REVIEW.md`는 원본 그대로 둔다. 사본 자체에 대한 반대 벤더
  검증은 하지 않는다(사용자 결정).
- **근거:** R-4·R-5의 차이가 가이드 문서 대부분에 흩어져 있어, 원본을 참조하면 에이전트가 매번
  원문과 예외 목록을 합쳐 읽어야 한다. 사본은 규칙과 구조가 한곳에서 일치한다.
- **배제한 대안:**
  - 원본 참조 + 차이만 기록 — 위 문제.
  - 동기화 없이 완전 분기 — 원본의 개선이 따라오지 않는다.

## R-9. 모든 UI는 pywebview

- **선택:** 화면이 있는 연습은 모두 Python + pywebview로 만든다. 화면이 없으면 Python CLI다.
- **근거:** 앞으로 langchain·langgraph 같은 파이썬 라이브러리를 쓴다.
- **배제한 대안:** 파이썬이 필요 없으면 Electron(이전 기준) — 파이썬 라이브러리를 쓸 수 없고 연습
  사이에 코드를 복사해 쓸 수 없다.
- **반영:** `AGENTS.md` 기술 기준, `docs/refs/03-project-list.md`의 스택 표, Electron으로 계획됐던 연습
  플랜 3개(01-03 model-manager, 01-05 tray-assistant, 04-03 translator)를 pywebview 기준으로
  고쳤다(2026-10-04).
- **남은 일:** 01-05 tray-assistant는 트레이·전역 단축키·클립보드가 pywebview에 없어 보조
  라이브러리가 필요하다. 보조 라이브러리 선택과, 트레이 상주 앱만 예외로 둘지는 그 연습의 미정
  항목이다.

## R-10. uv 환경은 연습마다

- **근거:** 연습끼리 독립시킨다(R-7과 같은 원칙).
- **배제한 대안:** 저장소 루트에 `pyproject.toml` 하나 — 한 연습의 의존성 변경이 다른 연습에 영향을 준다.

## R-11. VRAM을 넘는 모델도 연습 대상

- **선택:** 공유 GPU 메모리·RAM으로 넘쳐 도는 모델(예: `qwen3:30b` MoE)도 연습 대상에 넣는다.
  02-01은 `qwen3:30b`를 반드시 측정한다.
- **근거:** 사용자가 공유 GPU 메모리까지 쓰고 싶어 한다. MoE 모델은 활성 파라미터가 작아 넘쳐도 쓸
  만한 속도가 예상된다(`docs/refs/01-hardware.md` 5.3절, 실측 전).
- **배제한 대안:** GPU에 다 들어가는 모델만(이전 5.3절 판단) — 더 큰 모델을 시험할 수 없다.

## R-12. 우선순위 표기

- **선택:** `docs/refs/03-project-list.md`의 우선순위는 상·중·하로 적고, 번호(파일 이름)와 별개로 둔다.

## R-14. 저장소 문서는 `docs/`에 모은다

- **선택:** `INTENT.md`·`ROADMAP.md`·`DECISIONS.md`를 `docs/` 바로 아래에 두고, 참고 자료는
  `docs/refs/`(하드웨어·설치 가이드·연습 목록), 연습 플랜은 `docs/labs/NN-category/NN-name.md`에 둔다.
  루트에는 `AGENTS.md`·`CLAUDE.md`(자동 로드되는 파일), `workflow/`, `.claude/`, 연습 폴더만 남긴다.
  연습 폴더 안의 `docs/`(`current/`·`history/`·`refs/`·`reviews/`)는 그 연습의 문서라 층이 다르다.
- **근거:** 루트에 문서 파일과 문서 폴더가 연습 폴더 8개 사이에 섞여 있으면 연습이 늘수록 찾기 어렵다.
  지금은 git 저장소를 만들기 전이고 연습 폴더가 2개뿐이라 옮기는 비용이 가장 낮다.
- **배제한 대안:**
  - 문서 3개만 `docs/`로 옮기고 `refs/`는 루트에 두기 — 루트에 문서 폴더(`refs/`)와 `docs/`가 공존해
    어디가 어딘지 흐려진다.
  - `workflow/`도 `docs/workflow/`로 옮기기 — 프로젝트에서 따르는 절차 사본은 문서가 아니라 도구
    위치로 두는 편이 낫고, 사본 안의 경로·규칙 수정량이 크다.
  - 이전 `refs/labs/`를 `docs/plans/`로 옮기기 — 연습 폴더 구조(`NN-category/NN-name`)와 같은
    `docs/labs/`가 대응하기 쉽고, 연습의 `PLAN.md`와 이름이 겹치지 않는다.
