# 02-03 quant-compare — 양자화 수준별 속도·품질 비교

## 1. 개요

같은 모델을 양자화 태그만 바꿔(예: `q4_K_M`, `q8_0`) 받아 속도·VRAM·출력 품질을 비교하는 CLI다.
Pascal GPU는 FP16 처리량이 낮아 4~5비트 양자화가 유리하다는 `01-hardware.md` 5.1절의 판단을 직접 확인한다.

- 양자화 태그 읽기(`ollama show`의 quantization)
- 같은 질문 세트에 대한 응답 차이 비교
- 속도·용량·품질의 균형 판단

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python CLI |
| 언어·패키지 | Python 3.13(uv), `ollama`, `numpy` |
| Ollama API | `/api/show`, `/api/generate`, `/api/embed`(답변 유사도) |
| 모델 | `qwen3:4b`의 양자화 태그 2~3종, `bge-m3`(유사도 측정) |
| num_ctx | 4096 |

## 3. 간단한 플랜

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 태그 확인 | 비교할 태그 목록과 각 태그의 파일 크기·양자화 값이 표로 출력된다 |
| 2 | 속도·VRAM | 태그별 tok/s·VRAM_MiB가 02-01과 같은 방식으로 CSV에 기록된다 |
| 3 | 품질 | 질문 10개에 대해 태그별 답변과, 가장 높은 정밀도 태그 답변과의 임베딩 코사인 유사도가 표로 나온다 |

## 4. 하드웨어 메모

- `q8_0`은 파일이 4비트의 약 2배다. 8B를 `q8_0`으로 받으면 VRAM 여유를 넘을 수 있으므로 4B 모델로 비교한다.
- 받을 태그 이름은 Ollama 라이브러리의 태그 목록에서 확인한다(태그 이름은 모델마다 다르다).

## 5. 미정

- 비교할 양자화 태그의 정확한 이름(설치 후 라이브러리 태그 목록에서 확정)
