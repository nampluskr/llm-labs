# 06-04 scan-ocr — 스캔 PDF·이미지 텍스트 추출

## 1. 개요

스캔 PDF와 이미지(jpg·png)를 비전 모델로 읽어 쪽마다 텍스트를 추출하고, 문단·제목 구조를 살린
마크다운(`<이름>.ocr.md`)으로 저장하는 CLI다. 04-03 translator가 다루지 않는 "텍스트가 없는 PDF"를
여기서 텍스트로 바꾸고, 그 결과를 translator의 md 입력으로 넘긴다.

- 스캔 PDF를 쪽 이미지로 렌더링하기(해상도와 정확도의 관계)
- 비전 모델로 "보이는 글자를 그대로 옮기기" 프롬프트와 지어내기(환각) 확인
- 정답 텍스트 대비 문자 오류율(CER)로 정확도 재기

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python CLI |
| 언어·패키지 | Python 3.13(uv), `ollama`, `pymupdf`(PDF 쪽 렌더링, 텍스트 레이어 유무 확인), `pillow` |
| Ollama API | `/api/chat`(`images`) |
| 모델 | `gemma3:4b`(비전). OCR·문서 특화 비교 대상: `deepseek-ocr`(6.7GB, OCR 전용, md 변환 지원, Ollama v0.13.0 이상), `qwen2.5vl:7b`(6.0GB, 문서·표 인식), `granite3.2-vision`(2.4GB, 문서 이해 특화) |
| num_ctx | 8192(쪽 이미지 + 쪽 전체 텍스트 출력) |

## 3. 간단한 플랜

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 한 쪽 | 이미지 1장에서 텍스트를 추출해 출력하고, 쪽당 소요 시간을 표시한다 |
| 2 | 정확도 | 정답 텍스트를 아는 시험 이미지 10장(글자를 렌더링해 만든 이미지 5장 + 실제 스캔 5장)의 CER을 장별·평균으로 출력한다. 렌더링 해상도 2단계(150·300dpi)를 비교한다 |
| 3 | PDF 일괄 | 스캔 PDF를 넣으면 쪽 수만큼 처리해 쪽 구분이 있는 `<이름>.ocr.md`를 저장한다. 텍스트 레이어가 있는 PDF는 OCR 없이 "텍스트 PDF — 04-03으로 바로 번역"이라고 알린다. 중단 후 다시 실행하면 끝난 쪽은 건너뛴다 |
| 4 | 번역 연계 | 영어 스캔 PDF 1건을 `scan-ocr` → 04-03 translator 순서로 처리해 `<이름>.ko.md`가 나온다 |

## 4. 하드웨어 메모

- `gemma3:4b` 예상 VRAM 약 4~5GB. 쪽마다 이미지 1장 + 긴 출력이라 쪽당 수십 초가 걸릴 수 있다. 실제 속도는 Phase 1에서 잰다.
- 해상도를 높이면 작은 글자는 잘 읽지만 이미지 토큰이 늘어 느려진다. Phase 2 결과로 기본 dpi를 정한다.
- 작은 비전 모델은 안 보이는 글자를 지어낼 수 있다. CER과 함께, 정답에 없는 문장이 들어간 사례 수를 기록한다.
- 비교용으로 전용 OCR 엔진(예: Tesseract)을 붙이는 것은 이 프로젝트 범위 밖이다. 비교는 Ollama에서
  도는 모델끼리만 한다.
- 비교 대상 모델(`01-hardware.md` 5.2절):
  - `deepseek-ocr`는 프롬프트 형식에 민감하다. 이미지 다음 줄에 `<|grounding|>Convert the document to
    markdown.` 또는 `Extract the text in the image.`처럼 줄바꿈·문장부호를 정확히 넣어야 한다.
  - `deepseek-ocr`·`granite3.2-vision`은 최대 컨텍스트가 각각 8K·16K다. 이 앱의 `num_ctx` 8192는
    `deepseek-ocr`의 최대치와 같다.
  - Pascal(1080 Ti)에서 도는지와 쪽당 속도는 설치 후 확인한다.

## 5. 미정

- 시험용 스캔 문서의 선정(개인정보가 없는 것)
- 비교 대상 모델을 어느 Phase에서 비교할지(예: Phase 2 CER 표에 모델 축 추가)
