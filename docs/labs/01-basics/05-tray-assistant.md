# 01-05 tray-assistant — 단축키로 부르는 작은 질문 창

## 1. 개요

트레이에 상주하다가 전역 단축키를 누르면 작은 창이 뜨고, 클립보드의 텍스트를 넣어
"요약", "설명", "다듬기" 같은 동작을 바로 실행하는 pywebview 앱이다. 결과는 클립보드로 복사할 수 있다.

- 트레이·전역 단축키·클립보드를 파이썬에서 다루기(pywebview에는 없는 기능이라 보조 라이브러리를 쓴다)
- 동작별 프롬프트 템플릿
- 상주 앱에서 모델 적재 시간(`keep_alive`) 다루기

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python + pywebview |
| 언어·패키지 | Python 3.13(uv), `ollama`, `pywebview`, 트레이·전역 단축키·클립보드용 보조 라이브러리(예: `pystray`·`keyboard`·`pyperclip`, 선택은 미정) |
| Ollama API | `/api/chat`(stream) |
| 모델 | `qwen3:4b`(응답 속도 우선) |
| num_ctx | 4096 |

## 3. 간단한 플랜

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 상주·호출 | 단축키를 누르면 1초 안에 창이 뜨고, 클립보드 텍스트가 입력란에 들어 있다. Esc로 숨는다 |
| 2 | 동작 실행 | 동작 버튼 3개(요약·설명·다듬기)가 각각 다른 프롬프트로 스트리밍 응답을 보인다 |
| 3 | 결과 사용 | "복사" 후 클립보드 내용이 응답 텍스트와 같다. 트레이 메뉴의 "종료"로 프로세스가 끝난다 |

## 4. 하드웨어 메모

- 상주 앱이라도 모델을 계속 올려 두지 않는다. 기본 `keep_alive` 5분을 그대로 쓰면, 오래 쉬었다가 처음 부를 때 로드 시간(`load_duration`)이 붙는다.
- `qwen3:4b` 예상 VRAM 약 3~3.5GB.

## 5. 미정

- 전역 단축키 조합(다른 앱과 충돌하지 않는 키)
- pywebview에는 트레이 아이콘·전역 단축키·클립보드 API가 없다. 보조 라이브러리를 정하고, 창(pywebview)과 트레이·단축키 루프가 같은 프로세스에서 공존하는지 먼저 확인한다(스레드 구조)
- 모든 UI를 pywebview로 하는 기준(저장소 DECISIONS R-9)에서, 트레이 상주 앱만 예외로 둘지 여부
