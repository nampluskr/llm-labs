# 01-01 local-chat — 스트리밍 채팅 데스크톱 앱

## 1. 개요

로컬 Ollama 모델과 대화하는 pywebview 채팅 앱이다. 답변이 토큰 단위로 흘러나오고,
대화 중에 모델을 바꿀 수 있으며, 대화를 파일로 저장·불러온다. 모든 연습 프로젝트가 쓰는
"Ollama 호출 + 스트리밍 + 화면 갱신" 골격을 여기서 처음 만든다.

- `/api/chat`의 메시지 배열(system·user·assistant)과 스트리밍 응답
- 파이썬 → pywebview JS로 토큰을 밀어 넣는 방법
- `num_ctx`·`temperature`·`keep_alive` 같은 옵션의 효과

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python + pywebview |
| 언어·패키지 | Python 3.13(uv), `ollama`, `langchain-ollama`, HTTP 클라이언트(직접 호출용), `pywebview` |
| Ollama 호출 | 세 방식으로 앱 3개 — 공식 `ollama` 클라이언트 / `langchain-ollama` / HTTP API 직접 호출. 화면은 하나, 호출 층만 셋 |
| Ollama API | `/api/chat`(stream), `/api/tags` |
| 모델 | `qwen3:8b`(기본), `qwen3:4b`, `exaone3.5:7.8b` |
| num_ctx | 4096(설정에서 8192까지) |

## 3. 간단한 플랜

전제: Ollama 설치·모델 받기는 00-01, 파이썬 환경 확인은 00-02에서 끝나 있다.

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 세 호출 방식 노트북 | `notebooks/`의 `01-ollama`·`02-langchain-ollama`·`03-http-api` 노트북이 처음부터 끝까지 오류 없이 실행되고, 각각 스트리밍 응답과 tok/s를 출력한다 |
| 2 | 공통 호출 층 | 화면과 분리된 호출 층 3개가 같은 인터페이스를 갖고, 콘솔에서 세 방식 모두 토큰을 순차 출력한 뒤 tok/s를 한 줄 출력한다 |
| 3 | 채팅 화면(앱 3개) | 세 앱 각각 pywebview 창에서 질문 → 답변이 스트리밍으로 표시되고, 직전 대화 10턴이 문맥으로 전달된다 |
| 4 | 모델 전환·옵션 | 세 앱 각각 `/api/tags`의 모델이 드롭다운에 모두 보이고, 바꾼 뒤 다음 질문부터 새 모델로 답한다. `num_ctx`·`temperature` 값이 요청에 실린다 |
| 5 | 대화 저장 | 세 앱 각각 대화를 JSON으로 저장하고 다시 열면 같은 메시지 수로 복원된다 |

## 4. 하드웨어 메모

- `qwen3:8b` 기준 예상 VRAM 약 6GB(4K 컨텍스트). 평상시 여유 9.3GB 안이다. 00-01에서는 `qwen3:4b`만 실측했고 `qwen3:8b`는 아직 실측 전이다. 02-01 model-bench에서 실측한다.
- 모델을 바꾸면 이전 모델이 `keep_alive` 동안 메모리에 남는다. 두 모델이 동시에 올라가면 넘칠 수 있으므로, 전환할 때 이전 모델에 `keep_alive: 0` 요청을 보낸다.

## 5. 미정

- (결정됨) qwen3의 사고 과정(`<think>`)은 화면에 보이되, 생각하는 동안만 펼치고 답이 시작되면 접는다. 01-01 DECISIONS D-10 참고.
