# 04-05 log-analyzer — 로그 오류 요약·분류

## 1. 개요

긴 로그 파일(예: Ollama `server.log`, 빌드 로그)에서 오류·경고 구간을 규칙으로 먼저 골라내고,
그 구간만 LLM에게 넘겨 오류 유형 분류, 요약, 원인 후보를 받는 CLI다.
"전부 LLM에 넣지 않고 규칙으로 줄인 뒤 넣는다"는 전처리 설계를 익힌다.

- 정규식 전처리로 입력 줄이기
- 같은 오류의 반복을 묶기(중복 제거)
- 원인 "후보"와 확인 명령을 함께 내는 출력 형식

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python CLI |
| 언어·패키지 | Python 3.13(uv), `ollama`, `pydantic` |
| Ollama API | `/api/chat`(`format` JSON 스키마) |
| 모델 | `qwen3:8b` |
| num_ctx | 8192 |

## 3. 간단한 플랜

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 전처리 | 로그에서 오류·경고 줄과 앞뒤 3줄을 묶은 구간 목록, 같은 메시지 반복 횟수를 출력한다 |
| 2 | 분석 | 구간마다 유형·요약·원인 후보·확인 명령이 담긴 JSON을 만들고, `--json`과 사람이 읽는 표 출력을 모두 지원한다 |
| 3 | 실측 | 일부러 오류를 낸 로그 3종(Ollama, pip, npm)에서 사람이 정한 핵심 오류가 결과에 모두 포함된다 |

## 4. 하드웨어 메모

- Ollama 자신의 `server.log`를 분석할 때도 같은 Ollama를 쓰므로, 분석 요청 자체가 로그에 남는다. 분석 범위를 시간으로 자른다.
