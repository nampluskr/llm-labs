# 07-05 error-explainer — 명령 실패를 설명하는 래퍼 CLI

## 1. 개요

`ex <명령>`으로 아무 명령이나 감싸 실행하고, 실패(종료 코드 ≠ 0)하면 마지막 출력을 로컬 LLM에
넘겨 오류 원인 설명과 확인·해결 명령 후보를 받는 CLI다. 기존 도구(`youtube-kit`, `backlog`,
`speech_transcriber` 런처, `git`, `pip`, `npm` 등)를 **고치지 않고 바깥에서 감싸기만** 한다.
코드와 로그가 밖으로 나가지 않는다. 결과가 쓸 만하면 특정 도구에 넣을지는 연습을 끝낸 뒤 판단한다(INTENT 3절).

- 자식 프로세스 실행과 stdout·stderr·종료 코드 수집
- 출력이 길 때 앞뒤를 잘라 핵심만 넘기기
- 설명과 명령 후보를 구조화 출력으로 받기(명령은 제안만 하고 실행하지 않음)

## 2. 기술 스택

| 항목 | 내용 |
| --- | --- |
| 런타임 | Python CLI |
| 언어·패키지 | Python 3.13(uv), `ollama`, `pydantic`, `subprocess` |
| Ollama API | `/api/chat`(stream, `format`) |
| 모델 | `qwen3:8b` |
| num_ctx | 8192 |

## 3. 간단한 플랜

| Phase | 목적 | 완료 조건 |
| --- | --- | --- |
| 1 | 감싸 실행 | `ex <명령>`이 원래 명령의 출력을 그대로 보여 주고, 원래 명령과 같은 종료 코드로 끝난다. 성공하면 LLM을 부르지 않는다 |
| 2 | 실패 설명 | 실패하면 마지막 출력(최대 200줄)으로 원인 설명과 확인 명령 후보 3개 이하를 출력한다. 후보 명령은 실행하지 않는다 |
| 3 | 실측 | 일부러 실패시킨 명령 10개(pip·npm·git·기존 도구 CLI 포함)에서 사람이 판정한 "원인을 맞힌" 비율을 기록한다 |

## 4. 하드웨어 메모

- 성공한 명령에는 LLM을 부르지 않으므로 평소에는 VRAM을 쓰지 않는다.
- 대화형 명령(입력을 기다리는 명령)은 감싸지 않는다. 감지되면 안내하고 그대로 넘긴다.
